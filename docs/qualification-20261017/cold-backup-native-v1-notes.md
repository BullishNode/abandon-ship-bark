## Admission and proof limits

Literal test: `qualification_cold_backup::qualification_orderly_physical_backup_seed_only_recovery`. It requires a new test-only module declaration during coordinator integration, new exact source/ELF/metadata gates, the bitcoind chain source, actual BIP84 feature-selected BARK_EXEC/native fixture, local owned PostgreSQL, and an independently pinned `pg_controldata` from the same PostgreSQL toolset. Outer test deadline180s; no testcase retries. Standard native Daemon.start internally has its existing startup retries; this is not authorization to retry a failed testcase/funding sequence.

Native stop helpers can fall back to SIGKILL without exposing exit status to this test; independent clean PostgreSQL control state is therefore mandatory and a dirty copy fails. The service order is native TERM/reap followed by actual clean PG validation; this is not a separately instrumented proof of every service's graceful exit code. The case covers an ordinary same-candidate operator backup with continuing Core and separate fresh customer seed recovery. It does not claim Core backup, Lightning backup, arbitrary external PG, cross-version migration, universal backup, default daemon behavior, absent-original client recovery beyond this one ordinary seed path, or full ML coverage. Source review does not establish compilation, capacity, timeout sufficiency or a runtime PASS.
