## Money and chain checks reviewed

- All 327 independently generated owners have distinct real P2WPKH payout scripts and authenticated native fallback records. Each terminal is produced by the native cosign builder, registered through the native public API, and posted to that owner's actual blinded mailbox. The final ledger assertions now bind the terminal ID, owner mailbox, owner public key, registered script and actual payout parent.
- Each owner must receive exactly one independently unspent Core output of 4,000 sat with at least six confirmations. Each corresponding allocation must record gross 5,000 sat, fee 1,000 sat and forfeiture zero. This establishes 1,308,000 sat paid and 327,000 sat in declared customer fees for 1,635,000 sat gross; the fee is per actual distinct payout output because scripts are unique and output multiplicity is checked.
- Each observed physical package is fetched from Core; its parent must have version 3, vsize at most 10,000 and actual input sum equal to output sum. Its unique P2A spender must appear in the same canonical block, have version 3, vsize at most 1,000 and a strictly positive independently computed miner fee. The prior physical backing must have been confirmed in an earlier block.
- Graph completion includes every confirmed native signed path in addition to payout parents and their actual sponsors. Final graph transactions must all have at least six confirmations. Each input outpoint may appear once. External graph inputs must be the genuine original backing or one of the explicitly funded watchman outpoints. Every unconsumed graph output is independently fetched with `get_tx_out(..., Some(true))`; an omitted spender of such an output causes failure instead of silently becoming change.
- The final Core equation is `consumed external backing/sponsor value = independently unspent graph outputs + actual miner fees`. It includes intermediate progression, sponsor change and operator drains. Declared but unused initial watchman funding is outside this consumed-graph equation; it is not silently counted as spent. This is actual chain accounting, not a claim that stored `expiry_fee_child.fee_sat` or an unrelated wallet balance projection was reconciled.
- Active customer allocation count must equal 327, all original terminals must reconcile to confirmed parents, and stored confirmation hashes must equal Core's actual canonical payout blocks. No additional intermediate coin can add an active customer allocation while these checks pass.
- The source wallet/client and public/mailbox RPC handles are dropped before expiry. Subsequent test actions observe native background work, read Core/DB state and mine regtest blocks. No payee wallet is opened, and no test helper refreshes, signs, manually broadcasts a progression transaction or repairs registration after abandonment. Owner key material retained for expected-value comparisons is not used to assist expiry execution.
