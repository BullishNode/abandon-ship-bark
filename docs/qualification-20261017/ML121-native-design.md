## Minimal genuine path and what it would establish

Use one genuinely registered SDK owner, one 100,000 sat original coin O and one same-owner 100,000 sat self-refresh replacement R on a different anchor. Let the real server accept the original's complete native forfeit before any original exit. Lose only the actual successful reply, retain the SDK's durable signed-but-locked replacement checkpoint, stop both product daemons, and let the unchanged SDK recover the original coin through its actual delayed USER claim. After that claim reaches six confirmations, drop/fence the owner permanently. Restart the same product state, let R reach its real expiry with funded watchman, and observe the whole old/new lineage through positive financial closure.

This tests a genuine outage recovery path to the same account/script. No alternate beneficiary, incorrect-payee request, arbitrary signed transaction fabrication, financial SQL setup, forfeit-marker edit or lost-signature invention is needed.

## Exact independent starting model

Before the held request, freeze public IDs, actual funding transactions/anchor outpoints, full original signed path, registered fallback record/script, original user key, native round/participation ID, actual requested output policy and amount. After the genuine accepted reply, capture the SDK's persisted full signed replacement material and actual confirmed round funding. There must be exactly one input and one requested replacement for this first case, fee schedule actually zero, R.amount=O.amount=100,000sat, different anchors and a later real R expiry. Do not infer input/output linkage from equal amounts alone: bind the actual round participation, saved SDK output, policy/key, unlock hash and signed funding/path.

`server/schema.sql:1187` stores actual participation inputs and signed forfeits;`:1198` stores requested policy/amount/mailbox but **no replacement VTXO ID**. Therefore join the saved exact signed replacement/funding to its one actual request; do not invent a nonexistent output-ID column. Same ownership follows the one genuine SDK account's authenticated record and independently checked original/replacement normal-child keys, not merely equal payout scripts.

Validate complete original path against actual old funding. The private controller may validate an oracle copy of the replacement using the authentic withheld reply's unlock data, as existing checkpoint tests do; never inject that data into the original wallet or use it to claim R. Publish hashes/IDs/value only, never secret preimage/seed/invoice/config.

**Two distinct ledgers are mandatory.**

1. Physical value: both O and R have real independent backing; add actual customer exit-fuel and watchman sponsor inputs, then reconcile every canonical graph output and actual miner fee. A conserving 200,000 sat graph can still overpay the customer.
2. Economic obligation: there was one initial 100,000 sat customer principal exchanged by this self-refresh. For a sole original claim input, independently compute `old_user_net + old_user_claim_miner_fee = 100,000sat`. That exhausts this principal. A subsequent R customer payout/claim is a second discharge, even though funded by another valid operator-funded root. Exit CPFP fees paid from separately declared customer onchain fuel are tracked separately, not silently deducted from the original Ark obligation. A fallback fee is counted only for a justified actual customer payout; do not authorize a second 1,000 sat charge merely to make sums balance.

The expected ML121 one-principal rule must be explicitly accepted before the future verdict. A generic old-root spend cannot suppress a legitimately transferred recipient (ML122), and an unenforceable/unconfirmed old claim is not discharge. If contract instead allocates this outage risk differently, obtain the exact accepted rule before writing a false assertion; source inspection alone cannot decide that financial contract.

- The authentic old USER claim is canonical and independently pays the recorded owner. Resolve actual canonical transactions/anchor-spending sponsors through Core; only confirmed canonical versions count. Read null inactive unbroadcast parents safely. No unused intended path is counted as payment.
- One-per-outpoint physical DAG: external inputs are the declared captured customer initial funding, operator replacement anchor value and watchman outputs; customer board/change reuse and package drain/change are internal edges. Include all canonical source/board/exit/claim/payout/sponsor transactions needed to close that cut. Verify every surviving output's exact script/value via Core, and require inputs=remaining+actual fees. Do not double-count the old root and its included board funding as two externals. Any 330 sat/zero anchor residual is explicit, never customer principal.
- One economic discharge across O/R: the actual old claim's principal credit exhausts 100,000 sat. No R customer allocation/history/claim or owner-script output can create additional principal; scan every canonical graph transaction, including sponsors and any other recipient, not only the expected fallback parent. Preserve exact accepted original/R owner bindings. Independently distinguish operator-owned recovery from customer value and all actual fees.
- **Positive R closure** is required: R backing must actually reach an appropriate operator recovery/canonical resolution consistent with the accepted one-principal rule, with exact stored parent/child/paying hashes matching Core and no new customer payout fee.
