## Finding

**P2 — The history oracle only excludes duplicate debits inside the fallback subsystem.** [The initial history read](/home/francis/abandon-ship-fresh-integration/testing-track-worktree/testing/tests/server/expiry_transfer_refresh.rs:125) removes all other subsystems; [the summarizer](/home/francis/abandon-ship-fresh-integration/testing-track-worktree/testing/tests/server/expiry_transfer_refresh.rs:161) does the same on repeated sync/reopen. Therefore an extra negative movement consuming either original coin under another subsystem can coexist with correct fallback entries and the test still passes its “debited exactly once” assertion. This matters because the product history projector explicitly preserves regular movements before appending fallback projections (`bark/src/fallback/payouts.rs`, `FallbackSnapshot::project`). The review found an assertion blind spot, not an observed product double debit.

Suggested focused improvement: preserve full pre-return history, and compare full post-return history for any newly added/changed negative movement consuming either original input. Require the complete relevant debit delta to equal 39,670 sat exactly once, while retaining current per-output movement ID, amount, fee and input-set checks. Apply the same check after repeated sync and reopen. Alternatively scope the stated acceptance strictly to fallback-subsystem idempotence and leave cross-subsystem double debit explicitly unqualified.
