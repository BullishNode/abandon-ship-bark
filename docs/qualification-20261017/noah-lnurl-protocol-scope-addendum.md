# Noah metadata binding: protocol scope and preserved campaign rule

This is a read-only interpretation addendum. It changes no verifier, accepted campaign requirement, original failure, source, service, credential or funding state.

The current [LUD-06 base specification](https://github.com/lnurl/luds/blob/luds/06.md) does not require the invoice metadata description hash. The upstream [explicit removal commit](https://github.com/lnurl/luds/commit/30339780e8f709b839b639c65a50ff99f8a0abcb) deletes the requirement to verify the invoice h tag against the exact metadata string's UTF-8 bytes and the associated server hashing instructions. Both current text and the actual primary Git diff were checked on 2026-10-17. The later file history includes that removal; this is not an inference from a third-party implementation.

[BOLT 11 tagged-field requirements](https://github.com/lightning/bolts/blob/master/11-payment-encoding.md#tagged-fields) allow exactly one d or h field. A plain-description invoice is therefore not malformed BOLT 11 merely because h is absent. If h is present, the reader must verify its description commitment. This note does not establish that all other Noah behavior complies with either specification.

The accepted October 12 campaign instructions and the admitted independent verifier separately require strict metadata binding before payment. Root explicitly instructed this investigation to preserve that requirement. The original callback rejection remains FAIL under that declared stronger acceptance contract. Nothing in this standards finding authorizes silently changing that contract or weakening its hash checks.

The actual historical receipt is preserved as `noah-actual-invoice-rejection-20261017-public-copy.json`, SHA256 `dcc4410247d48589b0ba1bd6f7f13c0725d649f663fccaad25b5373110544ab6`. It records one stock-8e68 callback at 2026-10-17 16:11:48 UTC, 5,000 sat, and the strict verifier's missing-h rejection before payment. It does not establish payment, funded swap, forwarding, fallback or seed recovery. Source tracing shows stock Noah advertises the complete metadata JSON but sends a human-readable memo to a provider path that can encode only a memo. Upstream Ark SDK warning-only checks do not satisfy the independent campaign gate.

If the product owner retains that strict integration target, a legitimate future change must carry an explicit, mutually exclusive 32-byte description digest across the caller, REST/SDK/RPC and node boundaries into hold's existing Hash variant. The caller must commit to the exact advertised metadata bytes; hashing only the human memo or globally reinterpreting existing memos is insufficient. Existing memo behavior must remain intact. Unchanged stock Noah does not supply the digest, so adding a provider capability alone cannot repair this exact caller. An approved upstream-compatible integration change and separately admitted strict callback proof would still be needed. This testing track has not implemented a Noah fork, modified mobile code, changed acceptance policy or repeated the callback.
